# v2.4.4 — 它现在有名字了：鲸坞

这一版有三个独立的变化，按影响面从大到小：**改名**、**概览页多了一块内存栏**、
**远程 DSH 的第一版（实验性）**。

## 一、改名叫鲸坞

"桌面壳"是个工程黑话，念出来也不好听。新名字是**鲸坞**：

- 鲸 —— DeepSeek 的符号，也是这个生态里大家都认得的那只鲸鱼；
- 坞 —— 船进坞是为了停泊、检修、补给。这个程序管的正是版本锁定、回滚、
  重装、数据迁移这些"进坞维护"的活。

**技术标识一个都没动**：仓库还是 `pudaa/dsh-launcher`，产物还是 `DSH-Web.exe`，
数据目录还是 `%LOCALAPPDATA%\DSH-Web`。

这不是偷懒。自动更新的做法是"去 Release 里找和当前 exe 同名的资产"——exe 一改名，
已经装了旧版的人就再也升不上来；数据目录一改名，等于换了个应用，登录态和会话全丢。
所以名字只改给人看的那一层：窗口标题、托盘、菜单、关于、这份说明。

## 二、概览页加了「内存占用」

以前要知道它占多少内存，得开任务管理器，然后在
`DSH-Web.exe` / 若干个 `QtWebEngineProcess.exe` / 一堆 `node.exe`（还混着别的产品的）
之间自己数、自己加。现在面板概览页直接给：

```
合计        1.6 GB　·　6 个进程
主进程      475 MB
网页        383 MB　·　2 个进程
后台服务    624 MB　·　2 个进程
```

三个刻意的选择：

**只显示私有内存。** 任务管理器那列"内存"是工作集，窗口一最小化就会掉到几十 MB，
看着像省了七百兆，其实一个字节都没释放。私有内存才是真实占用。卡片底下留了一句话
提醒这件事。

**按进程树归拢，不是按进程名。** 全机可能有十几个 `node.exe`，只认名字会张冠李戴。

**每 2 秒采样一次，跑在后台线程。** 一次采样 16 ms，挂着界面线程会让滚动发黏。

顺带一个实测数据，可以解释"为什么后台更省电"：把窗口最小化之后，私有内存
从 1594 MB 降到 1484 MB（**−7%**），降的全是网页那部分（Chromium 发现页面不可见，
跑一次完整 GC、丢掉可以重建的图块缓存）；**后台服务那 624 MB 一分不降**。

## 三、远程 DSH（实验）

面板「运行方式」页多了远程主机：填一台机器的 SSH 地址，连上去，在窗口里用它那台
机器的 DSH。

做法是**只借端口，不改绑定**：远端 DSH 仍然只听 `127.0.0.1`，用 SSH 把那个端口
搬到本机。官方把"只听本机"当安全边界（拒绝绑 `0.0.0.0` 的理由是 RCE），
我们不去绕它。

三个实现上的决定：

- **复用你系统里的 SSH**，不是在程序里另做一套。你 `~/.ssh/config` 里配好的别名、
  密钥、known_hosts 直接可用。
- **不收密码**。走密钥或 agent，配置文件里不存任何凭据。
- **不碰远端你没让它碰的东西**：只在 `~/.dsh-remote/` 里放 pid、日志、启动命令；
  停止时先核对进程启动时间，对不上就宁可不动手（PID 会被系统回收，无脑 kill 会杀错人）。

**为什么标"实验"：** 这条链路到发版为止只验证到"连不上时的错误提示是对的"。
"复用远端上次启动的实例"这一步没能在真机上跑通——我手上能用的测试环境
（MSYS、WSL）判定进程身份的语义和目标 Linux 不一致。功能是完整的，但这一段
需要真实环境确认。

## 顺手修的两处

**无数据时的占位符从 `—` 改成 `0 MB`。** 破折号在那个字号下只有十几个像素，
缩略看和空白没区别，我自己就误判过一次"这行没渲染出来"。

**一条自测断言写死了旧名字。** 「DSH 更新与自身更新分开呈现」那条，原先只认
"桌面壳"或"Launcher"两个字样，改名后菜单里两样都没有——它会一直报失败，
而它守的正是"别把两种更新混在一起"的语义。改成从产品名常量取。

## 升级

直接覆盖安装即可，设置、登录态、会话都在 `%LOCALAPPDATA%\DSH-Web` 里，不受影响。

远程功能在「控制面板 → 运行方式」里，第一次用需要一台能 SSH 免密登录的机器
（`ssh <别名>` 能直接进去就行）。用之前请确认你知道它是实验状态——出问题的地方
大概率在"复用远端已有实例"那一段，报错会明确告诉你它认为发生了什么。
