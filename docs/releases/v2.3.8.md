# v2.3.8 — 启动不再缩在左上角，控制面板不再卡，应用内复制修好了

这一版是三件事：两个你直接看到的毛病，加一次整体体检。

## 启动时网页不再缩在左上角

以前启动的一瞬间，网页视图会先以很小的一块出现在窗口左上角，然后才撑满。
原因是窗口里两层视图的叠放方式：早先用的是「只显示最上面那一层」，底层在切换
的瞬间拿到了错误的尺寸。

现在改成「两层都常驻，只把上层压在最上面」。网页从头到尾按窗口的真实尺寸布局，
无论窗口多大、什么时候画第一帧，都不会再有那一小块。**顺手也缓解了拖拽缩放时
的抖动**——以前每次 `resize` 都会重建一次布局。

## 「常规」页不再卡住

切进「常规」页会明显顿一下，因为那一页要现场统计数据目录：多少文件、多大、
缓存占多少。以前是在界面线程上同步走一遍目录树，文件多的时候（实测 6.6 万个文件）
要 5.8 秒，这期间窗口就是不响应的。

现在：

- 统计挪到后台线程，界面立刻可用，数字算完再补上
- 结果缓存 30 秒，来回切页不再重算（重进一次 0.003 秒）
- 目录太大时**不再硬算到底**：3 秒或 40 万个文件就停，显示成 `≥ 1.2 GB`
  （带 `≥` 说明是下限）
- 同时换掉了遍历方式，同样的目录从 **5.79 秒降到 0.74 秒**（快了约 8 倍）

数字也不再精确到个位（显示 `6.6 万` 而不是 `66,443`）——这类统计本来就不需要
那么精细，精确到个位只是让眼睛更累。

## 应用内复制真的能复制了

在应用里点消息的「复制」，以前什么都不发生，也不报错。原因是网页里要写系统
剪贴板需要宿主授权，而授权请求被我们**静默拒绝**了——网页那边既没报错也没重试，
你看到的只是「点了没反应」。

现在会按「是不是我们自己这个页面」来判断：同源（同一地址）的页面直接放行
剪贴板读写，其他页面一律拒绝。所以消息、代码块、回答的复制都恢复正常，
外来的页面依然拿不到你的剪贴板。

## 体检：退出、释放、阻塞

除了上面两项，还做了一次全项目体检，修掉了一批「感觉不到但一直在耗」的问题：

**退出与释放**

- 关掉最后一个窗口后，进程可能还挂在后台（托盘图标没了、任务管理器里还在）。
  现在关闭窗口不再被当成"退出程序"，退出统一走托盘/菜单那条路，并等后台线程
  收尾、释放网页视图和开发者工具窗口。
- 控制面板、对话框关闭后立刻回收；以前它们要等到下次垃圾回收
- 内联图标渲染加了缓存：同一图标首次 26.7 毫秒，之后 0.10 毫秒（快 260 倍）
- 控制台窗口关闭时会正确结束后台读取线程，不再留一个空转线程

**不该在跑的东西**

- 启动时清理旧版本解包目录的动作，以前会挡在启动路径上（要扫一遍临时目录），
  现在推迟 2.5 秒在后台做
- 「状态检测」页的检查项有 30 秒缓存，来回切页不再重复发起检查

**健壮性**

- 更新下载的进度回调从「每 64 KB 一次」改成「每 512 KB 或每 120 毫秒一次」。
  以前 120 MB 的包会触发近两千次跨线程回调，每次都要写日志、往文本框里插一行，
  自己把自己拖慢
- 解析 GitHub / npm 返回的 JSON 时，能容忍尾部多余内容（以前会整段判失败）
- 版本自更新、DSH 更新、数据统计等几处路径都补了自检断言，这些断言在每次
  发布前自动跑

## 升级方式

用「检查更新」直接升级即可。不用手动下载，也不会动 DSH 本身、会话和登录态。
