# v2.6.0 — 版本管理

这次的主线是**版本管理**：私有安装不再只有一份，"更新"和"回退"从覆盖式安装
变成多版本共存。另外加了启动途径选择，以及一批界面文案的收敛。

## 版本管理

以前私有安装只有一份，"更新"和"回退"都是对它做覆盖安装，后果是：

- 回退其实是重装（实测 397 秒、656 个包）
- 只能回退一步
- 预发布版本一旦被 npm 撤包，就再也回不去
- 用户没法"装了但不用"——点一次更新，旧版当场消失

现在每个版本一份独立目录（`versions/<版本>/`），切换只改指针：

| | 以前 | 现在 |
|---|---|---|
| 更新 | 覆盖当前那份 | 装到新目录，旧的留着 |
| 回退 | 重新下载旧版 | 切回去（**34 秒**，其中 20 秒是服务启动） |
| 装坏了 | 当前版本已经没了 | 只是多一个坏目录，删掉即可 |

**「版本管理」页**（侧边栏第五项）：列出已安装版本、切换、删除、写备注。
切换前能看到每个版本的插件兼容情况——读插件声明的 `engines.dsh`，
声明不兼容的会标出来（只统计声明了的，没声明显示"未声明"，不当成兼容）。

**装新版本**：填版本号或 `latest` / `next` / `alpha`，装进独立目录。
装完不影响正在跑的服务。

**系统安装导入**：机器上另有一份系统级 DSH 时，可以让它复制一份进版本库。

**磁盘**：每版约 700–1100 MB。更新完成后如果总占用超过 2.5 GB 或版本数超过 3，
会问一句"旧版本要留着吗"。

## 启动途径

打开鲸坞时先起谁，可以在「运行方式 → 启动时」里选：

- **先起本机**（默认）
- **直接连远程**——打开就是远程，本地服务不起（实测 1.3 秒连上）
- **每次询问**

没配远程主机时，后两项不可选。

## 远程

- **连不上远端时本地服务不受影响**。此前每次点「连接」都会先停掉本地，
  连失败后什么都不剩，只能重启应用。
- **断开远程会自动切回本地**。
- **「保留本地服务」开关**：开启后连远程不停本地，切回来是 0.1 秒
  （关掉时约 20 秒）。代价是多占 600 MB 左右。
- 远端没装 dsh 时提示改成"请先执行 npm install -g @deepseek-ai/dsh@latest"，
  原来是裸的 `sh: 1: dsh: not found`。

## 界面

- 侧边栏重排：概览 / 常规 / 运行方式 / 本机部署 / 版本管理 / 状态检测 / 关于。
  "常规"提到第二项，"版本管理"跟在"本机部署"后面。
- 20 处界面文案收敛。最大的冗余是悬停提示和常驻文字说同一件事，
  现在悬停只回答"为什么"，常驻只回答"是什么"。

## 已知限制

- 所有版本共用同一个 `DSH_HOME`。切回旧版时，如果新版改过会话记录格式，
  旧版可能读不了。**切换前请留意**。
- 「保留本地服务」开启时，两个 DSH 同时常驻，内存翻倍。
- `last_good_version` 仍在写入，但回滚已不依赖它下载。
- 远程功能仍标「实验」：链路已在真实 Linux 主机上对真实 DSH 验证通过，
  但多用户场景未覆盖。
