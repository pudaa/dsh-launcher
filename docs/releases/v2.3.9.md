# v2.3.9 — 修掉「启动后连不上后端」

这是一版紧急修复。v2.3.8 之后有用户遇到：桌面壳起来了，但界面报 **401**、
提示连不上 web 端，重启也不一定好。根因在「怎么判断后端已经好了」这一步。

## 出了什么问题

启动流程是这样的：拉起 DSH 服务 → 等服务把它自己的访问地址（**带令牌**）打印
出来 → 用这个地址加载界面。

这里有两个地方做错了：

**一、等不及就退回一个不带令牌的地址。** 原来的实现最多等 3 秒，超时就"退而
求其次"，用 `http://127.0.0.1:端口/` 这种**没有令牌**的地址去加载。而这个后端
对没有令牌的请求一律回 401——于是界面看到的永远是「连不上」。

**二、认领旧地址时可能配错令牌。** 服务的日志文件是**追加**写的，里面留着历史
上每次启动打印的地址（换过端口的、别的实例的）。原来的逻辑取第一条匹配的，
就可能拿着**上一次的令牌**去连**这一次的端口**，结果同样是 401。

## 现在怎么做的

- **不再退让**：一直等到日志里出现**带令牌的、端口对得上的**地址为止。
  等不到就明确告诉你「后端在跑但拿不到访问令牌」，而不是静默降级成一个必然
  401 的界面。
- **只认当前端口**：日志里有多条历史地址时，按端口过滤，并且取**最后一条**
  （最后写进去的一定是最新启动的那次）；令牌只在「全文件只有一个候选」时才敢用。
- 等待上限从 3 秒放宽，读取日志的窗口也加大——服务在初始化插件、重试账号接口
  时可能十几秒才打印地址，这段时间不该被误判成"启动失败"。

## 顺带修的自测问题

排查时发现，自带的接口自测脚本会**覆盖掉正在运行的服务状态文件**
（`service.json`），而那个文件里存的正是端口和令牌。这会让下一次启动"找不到
现成的服务"，从而另起一个实例——也就是 401 的另一条触发路径。

现在自测跑之前会备份这个文件、跑完恢复。**日常使用不受影响**，这条只是防止
"跑自测把自己搞坏"。

## 如果你现在正卡在 401

升级到本版即可，不需要手动清理任何东西。如果升级后仍然连不上：

1. 退出桌面壳（托盘菜单 → 退出）；
2. 重新启动一次——它会把当前在跑的服务重新认领回来，不会再另起一个。

你的会话、登录态、聊天记录都没有被影响过，这一版也没有改动任何数据。

## 升级方式

用「检查更新」直接升级即可。
